# 运输分配：首个本地解析增量

本版已接通中文受限解析、JSON 合同、LP 求解、独立业务验算和会话版本。规则模式无需语言模型；自由表述可交给显式配置的本机模型生成待核对草稿。真实小模型效果尚未测量。

## 直接体验

启动现有应用，在新的主对话中粘贴下面的内容即可求解，无需上传文件：

```text
运输分配；
供给点 A 供给 20 吨；供给点 B 供给 30 吨；
需求点 X 需求 10 吨；需求点 Y 需求 30 吨；
A 到 X 单位运费 2 元/吨；A 到 Y 单位运费 5 元/吨；
B 到 X 单位运费 4 元/吨；B 到 Y 单位运费 1 元/吨；
最小化运输成本
```

最优成本为 **50 元**：A→X 运输 10 吨，B→Y 运输 30 吨，其余为零。每个需求点的最低单位运费分别为 2 和 1，因此 10×2+30×1=50 是可达到的下界。

也可以直接粘贴 [完整 JSON 示例](transportation_sample.json) 的内容。当前主对话入口支持内联 JSON 与上述中文格式；独立 Data MCP 可读取这个 JSON 文件。此增量不包含主页面运输 CSV 自动组装。

在同一对话继续输入：

```text
把供给点 B 供给改成 20 吨；先不求解
```

此时只保存新版本。再输入“继续求解”，最优成本变为 **90 元**。输入“比较最近两个方案”可看到成本增加 40 元；“撤销上次修改”恢复原始数据并得到 50 元。

支持同一条消息中的多项明确修改，例如：

```text
把供给点 B 供给改成 20 吨；把需求点 Y 需求改成 20 吨；先不求解
```

还支持“把 A 到 X 单位运费改成 3 元/吨”及“禁止 A 到 X 运输”。恢复禁运线路需要重新提交完整数据并明确运费。

## 输入合同与边界

| 字段 | 含义 |
| --- | --- |
| `suppliers` | `name` 与非负 `supply`，供给为上限 |
| `consumers` | `name` 与非负 `demand`，需求必须恰好满足 |
| `routes` | `source`、`target` 与非负单位运费 `cost` |
| `forbidden_routes` | 显式禁止运输的 `source`、`target`；可为空 |
| `quantity_unit` | 所有供给、需求和运费分母共用的数量单位 |
| `currency` | 所有费用共用的币种 |

每个供需组合必须明确提供运费或列入禁运，不能二者同时出现。首版最多 200 个组合；运输量为非负连续值，供给允许剩余，不允许缺货。未知字段、重复节点或线路、重复 JSON 键、缺失单位以及非有限数值会被拒绝。

受限中文入口支持吨、千克、公斤、件、箱，以及元或美元；不自动换算混合单位。JSON 可声明其他统一单位，但不会替用户判断数据是否确实使用该单位。

车辆数、时间窗、整数运输量、线路容量、多商品和其他目标尚未支持。完整 JSON 前后的额外自然语言条件也会被检查，不会因为 JSON 数据合法就忽略它们。未识别的表达会要求重新描述；首版不把多轮零散供需片段自动拼成完整模型。

供给不足或禁运造成断路时，数据可以是合法的，但模型不可行；此时返回 `INFEASIBLE`，保留诊断，不重复求解同一输入。

## 本地小模型接入

应用沿用现有模型配置：兼容接口地址、模型名及服务所需的认证设置。新增运输草稿接口首版仅允许 `localhost`、`127.0.0.1` 或 `::1`，不使用远程兜底，也不自动下载权重。

当受限规则无法解析运输描述，且已配置本机模型时，系统通过 `response_format` 传入 JSON Schema。模型需要返回完整候选数据、缺失信息、不支持的条件及原文依据。响应还会经过严格字段与数据校验。超时、Schema 不支持、输出错误等失败保留澄清状态，并在 `parser_attempt` 中记录故障类型。

本地模型草稿尚未证明与原文语义等价，因此会完整展示供需、运费、禁运线路和单位。核对后输入“确认运输草稿并求解”才创建有效版本；“继续求解”不会隐式确认草稿。规则可完整解释的输入则直接执行。

## 验证与评测

```bash
# 在项目根目录运行运输合同、求解、API 和模型接入控制逻辑测试。
.venv/bin/python -m unittest tests.test_transportation -q

# 运行 40 条人工编写的解析开发案例，并对有参考目标的案例实际求解。
.venv/bin/python scripts/evaluate_requirement_parser.py --solve

# 本机模型服务就绪后，将 YOUR_LOCAL_MODEL 替换为实际模型名。
.venv/bin/python scripts/evaluate_transportation_model.py \
  --base-url http://127.0.0.1:11434/v1 \
  --model YOUR_LOCAL_MODEL
```

规则报告默认保存到 `data/benchmarks/requirement-parser.json`；真实模型报告默认保存到 `data/benchmarks/transportation-model.json`。两份报告明确区分规则与模型。模型评测使用八条自由表述开发样例，检查完整参数、缺失信息和不支持条件，并记录延迟；它不是冻结测试集，不包含内存峰值或冷热启动分离测量。

本次开发基线的 40 条案例全部通过，带参考目标的 7 条案例通过真实求解与独立验算。这只说明这些已标注开发案例上的路由、门控和目标值符合预期，不代表任意业务语言的理解准确率。单元测试中的模拟模型输出只验证接入控制逻辑，不作为真实小模型成绩。
