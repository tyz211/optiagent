# 实时修复 Demo

本轮把已有的修复训练成果接入 Web：选择优化问题、故障和策略后，现场生成实例并执行一次真实 LangGraph 与 Solver Gateway 工作流，通过 SSE 展示节点进度、映射变化和独立验算。每次运行都有独立编号；结果来自新执行。

## 启动与使用

从项目根目录启动现有 FastAPI 服务：

```bash
# 使用当前已安装项目依赖的环境；该页面无需 LLM API Key。
.venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8001
```

打开 `http://127.0.0.1:8001/repair-demo`，也可以从主对话页的「实时修复演示」进入。页面提供六类问题、五种故障场景，以及规则、上一轮模型和新修复模型三种策略。

建议的演示顺序：

1. 保持「背包选择 / 持续映射错误 / 种子 7300 / 实例 0」，先选择「上一轮模型」运行。
2. 切换「新修复模型」再次运行。比较表只汇总同一问题、场景、种子、实例编号的实际执行记录。
3. 对照验算卡片：错误输入的返回目标为 106，按原始数据复算为 53；恢复原始映射后，两者均为 53。
4. 切换「无法修复的映射」，观察拒绝接受错误解并终止的路径。
5. 使用「下载本次结果」保留 JSON，其中包含请求、原始与错误数据、指纹、动作、验算事件、模型摘要和运行编号。

本次实际检查中，旧模型在持续映射错误上执行「重试求解 → 终止」，新模型执行「重建映射 → 接受」。这是固定演示案例的结果，不是新增的总体成功率测量。完整训练和多种子评测见 [修复 Demo 训练记录](repair-demo-training.md)。

比较记录只保存在当前页面内存中，刷新后清空。更改左侧配置不会修改已完成结果的身份；右侧「本次执行」会注明实际执行时的配置。显示的工作流耗时不包含子进程启动和模型初始化。

默认选择已有研究的固定 seed-11 检查点，没有针对本次演示结果重新挑选或训练模型：

| 策略 | 默认检查点 |
| --- | --- |
| 规则 | 不需要模型权重 |
| 上一轮模型 | `artifacts/rl/studies/20260919-five-seed-v2/runs/seed-11/recovery_policy.pt` |
| 新修复模型 | `artifacts/rl/studies/20260921-repair-demo/runs/seed-11/recovery_policy.pt` |

模型产物未纳入 Git。全新克隆后，先按训练文档生成检查点，或在服务启动前配置 `OPTIAGENT_DEMO_PREVIOUS_CHECKPOINT`、`OPTIAGENT_DEMO_CHECKPOINT` 指向兼容的本地权重。页面只检查文件存在和 PyTorch 可导入；文件损坏、内容不兼容或求解器不可用会在执行时明确报错。客户端不能提交任意文件路径。

`demo-2026.09.27` 完整本地交付包已附带这两份原始权重。直接解压、安装 `requirements-rl.lock` 并执行 `scripts/verify_demo.py --profile full`，即可校验文件摘要和实际修复行为，无需重新训练。获取与完整性说明见 [可复现交付说明](reproducible-release.md)。

没有检查点时，可以选择规则策略体验相同的求解与修复流程。缺失的模型选项会禁用；直接请求该策略返回 503，不会静默替换为规则。运行时策略推理回退仍按现有工作流合同记录，并在结果中显示次数。

演示独立于普通对话使用的 `OPTIAGENT_RECOVERY_CHECKPOINT`。它复用前一轮训练权重，本轮没有重新训练或更新网络参数。

## 执行边界

- 数据为确定性生成实例，故障为受控系数映射错误或一次传输失败；没有真实业务数据。
- 底层求解与对原始数据的独立验算真实执行。重建动作为确定性映射恢复器，不调用 LLM，也不证明自动改写任意模型代码的能力。
- 每次请求启动独立子进程，在临时 SQLite 数据库中保存该次工作流轨迹。故障补丁仅作用于这个进程，不读取上传数据，也不写入普通对话数据库。完成或取消后清理临时目录。
- 每个 API 工作进程最多同时执行 2 个 Demo，单次限制 90 秒。停止、断连、超时会终止子进程并归还名额；满额时返回明确的忙碌事件。多进程部署的总并发上限是工作进程数乘以 2。
- 页面下载是保留结果的方式。服务不永久保存演示运行记录，普通对话的生产轨迹导出不会包含这些案例。

## 接口与验证

`GET /api/demo/repair/catalog` 返回选项与策略可用性；`POST /api/demo/repair/stream` 接受 `template_id`、`scenario`、`policy`、`seed`、`instance_index`。其他字段拒绝；种子范围为 0–1,000,000，实例编号为 0–99。

SSE 事件依次包含 `started`、`input`、若干 `node` / `evidence`，最终为 `final` 或 `error`。每个事件携带单行 JSON；子进程普通输出不会作为协议事件传入浏览器。

新增自动化检查涵盖非法参数、缺失检查点、并发满额、提前关闭、超时、启动中取消，以及真实并发执行中的修复成功与安全终止。全量回归结果：116 项测试通过。浏览器验收还检查实际运行、新旧模型对比、安全终止、停止按钮和导出入口；最终页面无浏览器错误日志，390px 窄屏下页面宽度为 390px，无整页横向溢出。
