# OptiAgent Demo 交付说明（2026-09-23）

当前交付范围是本机可运行的运筹优化 Demo：主对话负责需求澄清、标准模板求解、数学验算和多轮修订；实时修复页面展示规则与训练策略的恢复行为。数据示例为人工构造或生成数据，未使用真实业务数据。本轮完善交互与状态管理，没有重新训练策略或更新 LLM 权重。

2026-09-27 增加固定依赖、带模型的本地交付包和统一验收入口，参见 [可复现交付说明](reproducible-release.md)。本文保留 09-23 的业务功能与历史验收记录。

## 启动

使用项目现有依赖环境：

```bash
# 自动选择可用端口，终端会显示实际访问地址。
./start.sh
```

打开输出地址的 `/` 进入主对话，`/repair-demo` 进入实时修复实验室。新建对话后点击「载入背包演示数据」，发送即可求解；这条演示路径无需配置 LLM。

本机已验证 Gurobi 可用。全新环境仍需安装项目依赖并配置可用的求解器许可；不同模板的求解器要求见 README。训练检查点不在 Git 中，全新克隆时实时修复页仍可使用规则策略，学习策略需按训练文档生成或配置检查点。

## 五分钟演示步骤

| 操作 | 可检查的实际结果 |
| --- | --- |
| 新建对话，提出背包目标但不提供数据 | 主动追问，不调用求解器 |
| 提供容量 5，A 的价值/重量为 8/3，B 为 5/2 | 选择 A、B，目标值 13，数据版本 1 |
| 发送「把容量改成 3，先不求解」 | 保存版本 2，本轮不求解 |
| 发送「继续求解」 | 仅选择 A，目标值 8，比较结果为 13 → 8 |
| 发送「比较最近两个方案」 | 返回已保存方案的比较，不再次求解 |
| 发送「删除容量约束」 | 明确提示暂不能执行，保留旧版本，不调用求解器 |
| 发送「撤销上次修改」 | 恢复容量 5，生成版本 3，再求解得到 13 |
| 刷新页面、查看有效数据、下载记录 | 保留原来的需求版本、运行记录与比较结果 |

页面快捷操作只填入输入框，发送后作用于会话的最新版本。每条历史消息的数据和下载记录对应当时的版本，不会随后续修改改变。目标值的增减表示业务条件变化，不能作为不同算法优劣的证据。

## 已交付的功能与范围

- 六种优化模板的求解、结果解释和数学验算沿用已有主流程。
- 五类内联 JSON 输入（背包、指派、旅行商、车间调度、产品组合）支持有效数据持久化、完整 JSON 替换、继续求解、暂停求解和版本撤销。
- 背包额外支持自然语言容量替换，例如「把容量改成 3」「把容量从 5 改成 3」。未知单位、错误旧值、混合未支持约束会被拒绝，不会悄悄求解旧数据。
- 当前有效 JSON 明确优先于会话中的其他上传文件或旧数据集编号；求解器只消费一份规范化输入。
- 会话内最近两个同模板、通过数学与工作流验算的方案可比较目标值及变化字段。最多从最近 100 条运行中寻找；不足两个时提示继续求解。
- 版本保留父版本、变更动作及来源轮次，支持连续撤销；每个会话最多 100 个数据版本，达到上限后提示新建对话。
- 同一个服务进程内拒绝同会话重叠执行；前端在运行期间锁定会话与数据切换。当前 Demo 使用默认单工作进程，多进程部署仍需要共享的并发控制。
- 实时修复 Demo 保持独立运行，支持故障场景、策略比较、实时证据与结果导出，见 [实时修复说明](live-repair-demo.md)。

## 仍属于后续扩展的能力

任意业务约束的自动增删和编译、自然语言修改任意 JSON 字段、仓库三表的统一版本编辑、任意历史方案分支与命名、复杂解释追问和对话策略强化学习尚未完成。当前内联结构化路径采用确定性操作；不支持的后续消息会请求澄清。切换新的独立业务问题建议新建对话。

本版本应作为限定模板和明确操作范围内的可交互 Demo 验收，不应作为任意问题均可自动建模的生产系统验收。
