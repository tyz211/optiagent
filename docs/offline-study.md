# 离线恢复策略多种子研究

本流程已完成一次完整五种子实验，结果与局限见 [实验报告](offline-study-results.md)。

## 目的与边界

回答“此前单种子、小数据集上的 CQL 成本收益是否能重复出现”。当前算法、奖励和验证选模规则保持原有版本，通过增加独立实例与训练种子验证结论。

这是实际 LangGraph、数学求解器与 verifier 执行配合受控故障反馈的实验；五类反馈包括正常、瞬时失败、目标不一致、模型错误和持续失败。模型错误场景仍是预设恢复条件，不代表网络学会自由修改优化模型。训练与评测不调用 LLM，也不更新 LLM 权重。

## 冻结数据与分组

默认每模板 train/validation/test/external 配额为 40/20/20/20，共六种模板，即 240/120/120/120 个独立实例。

采集前保存 `plan.json`，生成器只根据内容哈希和模板配额筛选候选，不运行求解或查看模型效果。
内部数据继续使用既有 `instance_sha256_70_15_15` 哈希归属函数，但满足配额后的集合比例为 50/25/25，不能理解为最终仍是 70/15/15。
外部实例使用独立生成坐标，并与内部数据及已知行为模型来源数据逐一检查内容重叠。

仓库选址先经过实际入库相同的 `normalize_data`，补齐最低利用率、强制启用/关闭等默认字段，再计算指纹。
这样显式提供默认字段与省略默认字段的样本不会被视为不同执行实例。其他模板沿用内容指纹合同；目前不处理变量重命名同构。

默认采集规则策略轨迹；提供冻结行为模型时，同时采集其轨迹，并要求提供来源实例文件。
来源文件的原始与规范化指纹都会排除。这个检查只能覆盖提供的已知来源，不能自动证明外部模型训练来源完整。

## 运行方法

```bash
# 仅规则轨迹的独立实验；输出目录必须尚不存在。
.venv/bin/python scripts/run_offline_study.py \
  --output artifacts/rl/studies/rule-only-v1

# 本轮使用此前已冻结的行为模型，并排除其来源实例。
.venv/bin/python scripts/run_offline_study.py \
  --output artifacts/rl/studies/20260919-five-seed-v2 \
  --behavior-checkpoint artifacts/rl/runs/20260917T173217+0800_seed55_ea4ab06f/recovery_policy.pt \
  --behavior-tasks artifacts/rl/runs/20260917T173217+0800_seed55_ea4ab06f/real_gateway_tasks.json
```

默认种子 11、22、33、44、55；每种子 BC 160 epoch、CQL 1500 次梯度更新；四个隔离采集/评测进程，PyTorch 与 Gurobi 每进程一个线程。
来源检查点与大文件不随 Git 提交；没有历史产物时可先运行真实 Gateway 训练入口生成自己的来源模型，但该实验不等同于本轮精确复现。

支持 `--phase prepare`、`--phase train`、`--phase evaluate` 分阶段执行。训练和评测阶段读取冻结配置，阶段间重新核对源码、数据、行为模型和检查点摘要。
同一阶段已有输出时拒绝覆盖；目前不支持从中途失败的批次自动恢复。失败结果保留，新实验使用新目录。

## 产物与评测

- `plan.json`：实例原始内容、规范化指纹、配额与已排除的来源指纹。
- `config.json`、`prepared.json`：训练参数、源码摘要、Git 状态、数据覆盖与输入摘要。
- `dataset/`：脱敏分组 JSONL、隔离记录和 manifest。
- `runs/seed-*/`：BC、末轮 CQL、验证选中策略检查点、训练曲线与报告。
- `trained.json`：训练完成时全部检查点的摘要。
- `evaluation-*.json`：每种子四策略的逐实例/场景结果、成本、调用数与安全检查。
- `summary.json`：种子均值/样本标准差、逐实例配对差异、验收判定和证据摘要。

所有模型训练完成后才执行外部测试。选模仍只最小化 validation 的记录动作回报误差，此指标只作诊断，不能证明策略价值改善。
配对比较先在同一实例的五种场景内平均，再汇总独立实例；训练种子共享测试集，种子方差不等于任务总体置信区间。

成本指标包括平均建模/求解调用次数、归一化恢复成本估计和墙钟耗时。
成本估计使用实际观测延迟，因此输入特征也可能随机器负载而变化；精确浮点指标不保证跨机器逐位复现。
墙钟时间包含临时建库、执行及轨迹导出，并受并发与执行次序影响，只作为诊断，不用来宣称策略加速。

每个种子的选中策略必须同时满足：无非法动作、无推理回退、无未验证结果接受；可恢复成功率不低于规则和 BC；相对两者建模调用严格减少、求解调用不增加。
至少五个种子全部满足才通过当前受控基准门槛。通过也不自动启用线上 checkpoint，`production_ready` 始终为 false。

## 扩容过程中发现的求解问题

首次大规模采集在调度实例 `recovery-instances-v2:6100:train:job_shop_scheduling:67` 上停止。
求解器报告最优，但独立验证器发现约 0.000135 时间单位的机器工序重叠。
修复将调度机器互斥改为条件约束，并将该模型的可行性/整数容差收紧到 `1e-9`；没有放宽验证器。
回归测试覆盖实例 2 与 67。冻结清单全部 100 个调度实例另行复查通过后，使用相同数据清单启动 v2 实验。
首次失败的清单与原因保留在 `artifacts/rl/studies/20260919-five-seed/`，没有通过删除困难样本来完成配额。
