## 3. 下一阶段：先验证稳定收益

进展更新（2026-09-20）：本节的覆盖扩容、五种子训练和独立配对评测已完成。
实际为 480 个内部实例、120 个外部实例、4,800 条采集轨迹、12,000 个外部执行案例；
五个种子均通过预设受控基准门槛，完整结果见 [多种子实验报告](offline-study-results.md)。
下一优先级改为验证成本收益的适用边界：加入实际数据/模型修复与更丰富的故障持续机制，
并单独研究基于真实 validation 执行结果的选模。新方案须使用新的外部测试集，避免反复针对本轮测试结果调参。

目前继续盲目增加合成训练轮数收益有限。优先扩充独立实例与评测覆盖，再决定是否修改算法。

1. **固定数据与评测合同。** 保留 train/validation/test 内容指纹隔离，增加数据采集规模；建议验证集、测试集分别至少覆盖每种模板 20 个独立实例。现有哈希划分不保证各模板数量均衡，须先检查覆盖率，扩充不足集合，不能看到模型效果后重划分。
2. **冻结外部测试集。** 建立与全部训练数据无内容重叠的六模板测试集，至少每模板 20 个实例，每实例保留五类受控场景。继续标明故障注入，真实求解执行不等于真实线上故障。
3. **五种子训练与配对对照。** 在同一固定数据集上用 11、22、33、44、55 训练，比较规则、BC、末轮 CQL、验证集选中 CQL。所有策略使用相同外部测试实例；测试结果不参与检查点选择。
4. **报告实际执行结果。** 记录总成功率、可恢复成功率、平均建模/求解调用数、非法动作与回退率、成本与延迟。报告每种子指标及均值/样本标准差，按实例统计配对差异，不能将同一实例的多个故障场景视为独立实例。
5. **验收后再启用策略。** 受控基准上每个种子都不得降低可恢复成功率，不接受未经 verifier 通过的结果；只有成本收益跨种子稳定、且独立评测达标，才考虑将 checkpoint 用于后续试运行。离线 Q 值误差下降不能单独作为上线依据。

现有单种子 CQL 实验的验证/测试独立实例仅 2/1 个，外部评测 24 个实例；此前约 11.9% 的建模调用下降是小样本受控结果，尚不能宣称普遍收益。

## 4. 后续依赖顺序

- 扩大并稳定 Agent policy 评测后，采集真正的失败—修复轨迹，补齐上传数据内容指纹，记录实际模型修改及 verifier 反馈。
- 再推进双主线路线中的模型训练数据合同：脱敏 messages、模型输出、模型版本与细粒度奖励，形成 SFT 数据视图。
- 有可验证的数据规模和基础模型评测后再启动 SFT，之后才讨论 GRPO。当前没有证据表明 LLM 权重已被训练。
