# 可复现本地交付：demo-2026.09.27

本版本冻结现有多轮对话、六类优化模板、独立数学验算与实时修复演示。交付目标是：将压缩包放入一个新目录，安装锁定依赖，执行同一个验收命令，再启动演示。无需 LLM API Key，也不需要重跑历史训练。

## 交付物与适用环境

- 完整包 `OptiAgent-demo-2026.09.27-full.tar.gz`：公开源码、示例、文档、测试、依赖锁文件，以及两份固定 seed-11 恢复权重。
- `SHA256SUMS`：压缩包完整性校验。它证明内容一致，不是发布者的数字签名。
- `release-manifest.json`：逐文件大小和 SHA256、源码整体摘要、交付配置与参考 Git 提交。包内也保留一份。
- 单独提供的验收目录：各阶段 JSON、日志及 `summary.json`。历史训练指标不能替代本次验收结果。

本次锁定环境为 **CPython 3.14、macOS arm64**，基准解释器为 3.14.0。依赖锁文件完整列出当前平台的依赖闭包；没有将本机无关包一起冻结。Linux、Windows、其他 Python 版本尚未纳入本次验证，不宣称跨平台复现已经完成。开发用的 `requirements.txt` / `requirements-rl.txt` 保留宽版本范围，交付验收使用 `.lock` 文件。

包内不包含 Python、第三方依赖安装包、Gurobi 许可证、用户数据库、上传文件、API 配置或完整研究数据集。安装依赖需要访问包源或事先准备的缓存。Gurobi 仍需当前机器有可用许可；小型演示是否可运行以统一验收的真实求解结果为准。

## 新环境：完整演示

将完整包、`SHA256SUMS` 放在同一目录，先验证，再解压。以下步骤在解压后的项目根目录执行；目录可以包含空格或中文，不依赖作者机器的绝对路径。

```bash
# macOS 中校验交付文件；应看到 OK。
shasum -a 256 -c SHA256SUMS
tar -xzf OptiAgent-demo-2026.09.27-full.tar.gz
cd OptiAgent-demo-2026.09.27

# 使用独立环境，避免继承已有环境中碰巧安装的依赖。
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-rl.lock

# 必须得到 passed；完整模式不会悄悄跳过学习策略和训练测试。
.venv/bin/python scripts/verify_demo.py --profile full
./start.sh
```

打开终端显示的地址，`/` 是主对话，`/repair-demo` 是实时修复实验室。启动默认不启用开发热重载，使用单个服务进程；开发时可显式 `RELOAD=1 ./start.sh`。详细业务演示步骤见 [Demo 交付说明](demo-release.md)。

## 不安装 PyTorch 的规则模式

源码目录、core 包或 full 包均可运行规则模式。full 包中的模型文件存在也不会使规则模式依赖 PyTorch。

```bash
# 在一个新的项目副本中安装基础依赖。
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-demo.lock
.venv/bin/python scripts/verify_demo.py --profile core
./start.sh
```

基础模式覆盖对话、六类求解、数学验算、真实 MCP 通信及规则修复。报告明确列出未纳入的五个神经网络测试模块；这不代表全量训练测试通过。页面在模型或 PyTorch 不可用时禁用学习策略，仍可选规则策略。

## 统一验收合同

`scripts/verify_demo.py` 使用执行它的 Python，依次执行：

1. 核对依赖锁、解释器版本、包依赖一致性、源码快照；full 模式另核对两份模型摘要。
2. 检查启动脚本及两份前端脚本的语法；Node 缺失会明确记录前端语法未检查。
3. 执行所选模式的回归测试。失败、导入错误或未声明跳过均返回非零退出码。
4. 执行七轮真实对话：澄清、求解、暂停修改、继续、比较、拒绝不支持的操作、撤销。
5. 通过 ASGI HTTP 接口验证主页面、静态资源、主对话 SSE 与真实修复子进程。core 验证规则的恢复/终止；full 额外比较旧模型与新模型的固定案例行为。

所有对话使用临时 SQLite 数据库。验收固定恢复策略与演示配置，不读取已有用户会话或调用在线 LLM。运行记录写到新的 `artifacts/validation/<时间>/`；可通过 `--output 新目录` 指定位置，已有目录不覆盖。`summary.json` 的 `status` 必须是 `passed`。这是一组交付回归，未运行浏览器视觉检查，也未重跑历史研究训练或 19,500 个历史研究案例。完整回归中的训练单测会在临时目录执行短小训练，不覆盖随包提供的权重。

## 维护者重新生成交付包

```bash
# 必须在源码与两份原始权重都齐全时执行；目录不能已经存在。
.venv/bin/python scripts/build_demo_release.py --profile full --output artifacts/releases/demo-2026.09.27

# 未持有权重时可生成源码与规则模式包。
.venv/bin/python scripts/build_demo_release.py --profile core --output artifacts/releases/demo-2026.09.27-core
```

打包器按 `release/demo.json` 的范围读取当前源码，包括该范围内尚未提交的新增模块。它以内容摘要固化实际实现，Git 提交号只作来源参考；不会把旧 HEAD 冒充为全部代码版本。压缩包固定文件顺序、权限和时间，相同源码、权重及来源元数据产生相同包；从解压目录重新打包会保留原始来源元数据。解压后的目录不需要原仓库 `.git`、原虚拟环境或历史研究目录中的其他文件。

应在新目录解压最终包并安装锁定依赖，执行 full 验收；保存这一份包和报告一起交付。代码、配置或文档改变后需要重建并重新验收，不复用旧报告。
