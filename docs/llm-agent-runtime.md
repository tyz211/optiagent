# LLM 主控、上下文与记忆使用说明

## 启用方式

当前用户配置了模型后，`/api/ask` 和 `/api/ask/stream` 默认优先使用 LLM 主控，即使服务环境变量 `OPTIAGENT_AGENT_MODE` 为 `legacy` 也不会覆盖账户模型配置。请求字段 `agent_mode` 可选择 `auto`、`llm`、`legacy`；显式指定 `legacy` 可切换原有工作流。未配置模型且未传模式时读取服务环境变量（默认 `auto`）；显式 `llm` 缺少配置会返回 400。

模型配置与 API Key 按账户持久化到项目固定位置的 `data/optiagent.sqlite3`，更换启动目录或重启不会更换数据库。刷新页面或重新登录相同账户后，自动恢复服务地址、模型名称与温度；API Key 只显示“已保存”，不回传真实值。编辑已有配置时密钥留空或省略，保留当前账户的旧密钥；填写新密钥会替换。远程服务首次保存、或更换服务地址时，需要输入该服务的密钥。本机免密服务首次配置可留空。配置失败保留旧值；登录令牌失效时明确提示重新登录，不能改写匿名配置。

`legacy` 是原有流水线，保留其既有模型路由行为；不是严格离线模式。LLM 主控复用本地 Gateway 和 Solver，首版暂不开放任意外部 MCP 配置、任意代码生成或执行。

## 主控与验证

LLM 每次产生一个结构化行动：整理需求、读取可编辑字段、提交原文修改、检查数据、检索记忆/知识、建立模型、求解、验算、比较、读取已验算方案、选择解释事实、追问或完成。执行层根据状态列出可用行动；不满足条件的行动不执行，拒绝原因进入下一次上下文和审计轨迹。

本轮需求分析是使用当前数据版本的前提，不能因上一轮求解成功就跳过变更处理。数学验证通过后才能接受成功解；终止前求解记录标记为 `PENDING_VERIFICATION`，追问或预算停止后未接受的候选标记为 `UNACCEPTED_RESULT`。已证明不可行的运输问题不重复调用同一模型。

建模工具仍采用既有确定性合同与模板。2026-10-06 已增加带原文依据的数值修改和事实引用解释；任意业务约束编译、自由因果解释和不可行诊断仍待实现。

结果含 `agent_controller`（模型、停止原因、决策次数、工具次数、上下文统计），`agent_graph`（实际行动轨迹），以及既有验算报告。模型错误返回 `AGENT_ERROR`，预算停止返回 `AGENT_BUDGET_EXCEEDED`，追问返回 `NEEDS_CLARIFICATION`；失败不会伪装成规则模式的模型成功。

默认最多 12 次决策、单次输出预算 1400 token、输入保守估计预算 12000、总执行时间预算 180 秒。输出预算已随修改证据增加；长批次仍可能触及预算，需要减少修改数量。时间预算在调用边界检查，不能强制取消已经运行的本地求解器。建模和求解分别至多两次。

## 工具扩展结构

2026-10-07 将主控与工具业务逻辑拆开：

| 模块 | 职责 |
| --- | --- |
| `api/services/llm_controller.py` | 模型决策、上下文预算、行动审计、SSE、终止处理与候选接受 |
| `api/services/agent_decision.py` | 严格共享行动合同与工具参数模型 |
| `api/services/agent_tool_registry.py` | 工具注册、发现、参数验证和执行前条件复核 |
| `api/services/agent_tool_catalog.py` | 内置工具元数据、参数类型和各自的前置条件 |
| `api/services/agent_tools.py` | 本轮作用域上下文、工具处理函数和既有工作流节点适配 |

新增工具在应用启动阶段调用 `register_agent_tool(AgentTool(...))`，提供名称、中文标签、描述、Pydantic 参数模型、`precondition(state, counts)` 与 `handler(context, decision)`。工具会自动进入行动 Schema、可用行动列表、执行分派和审计；无需修改控制器中的固定枚举或执行分支。未知名称、重复名称、缺少处理函数或不受支持的参数字段会明确拒绝。

目前工具参数复用严格共享合同中的 `query`、`message`、`patch`、`run_id` 和 `fact_ids`。参数模型可使用其中部分字段并加强类型或值约束；执行前验证并使用规范化后的值。新增任意参数字段仍需演进共享合同和严格输出协议，不能仅靠注册生效。处理函数应返回适合进入下一次上下文的小型观察，完整数据保留在本地。

`finish` 和 `clarify` 保留为主控终止行动；扩展不能覆盖其注册或自行声明其他终止行动。本轮需求门控、成功解验算门控、重试次数、候选记录与解释来源在最终返回前的复核继续生效。工具注册不扩大其他用户、会话和数据集的访问范围，处理函数通过 `AgentToolContext` 使用当前作用域。

可运行的新增工具示例见 `tests/test_extension_registry.py`：注册检索工具后用脚本化主控执行真实求解链，并检查下一次模型反馈和持久化审计。

## 带原文依据的需求修改

已有有效背包或运输数据后，主控可选择 `read_requirement` 按实体或字段读取最多 20 个可修改目标，再用 `apply_requirement_patch` 提交最多 8 项同一版本的修改。其他模板继续使用既有需求工具，不能把不支持的字段写进补丁。

| 模板 | 可修改字段 | 明确指令示例 |
| --- | --- | --- |
| 背包 | 容量、已有物品价值和重量 | `将背包容量调整为 3`；`把物品A的价值改为 9` |
| 运输 | 已有供给点供给量、需求点需求量、已有可运输线路单位运费 | `把S的供应量改为 8 吨`；`把从S到T的单位运费改为 3 元/吨` |

支持“改成、改为、调整为、设为、设置为、调整到、修改为、降低到、降低为、提高到、提高为、增至、降至”等明确替换动词。多个修改句用分号分隔；`先不求解`、`暂不求解`、`只修改` 等控制指令要求 `mode=hold`，之后可用既有“继续求解”指令执行。

每项补丁携带字段、已存在实体、替换数值、本轮原文和字符起止位置，以及共享的基准版本。工具逐项检查原文位置、实体名称、明确替换语义、数值、旧值（如声明“从 5 改为 3”）、增减方向、精确单位、重复字段和本轮条件覆盖，再校验完整候选数据。单位可以省略沿用原单位，但明确写出的单位必须一致；未声明单位的背包数据不允许擅自解释成千克。任何不支持或未消费的条件都会拒绝整批，旧版本不变。

所有检查通过后，在 SQLite 同一事务中比较完整旧需求状态并保存完整新状态，避免同一版本号下的其他状态修改被覆盖。需求历史和每项修改依据一并保留，不删除旧版本；沿用现有每会话 100 个版本上限。冲突时返回具体拒绝原因，主控可重新读取或追问。本轮成功修改即完成需求分析前置条件，求解始终使用新版本生成的请求。未澄清的旧条件或待确认运输草稿不能通过补丁静默清除。

这是有明确能力边界的语义修改工具；不新增实体、改变目标、增加任意约束或进行单位换算。仅引用一句包含复杂条件的原文，并不能证明条件已被执行。

## 已验算方案读取和事实解释

可输入 `解释上一轮方案`、`说明当前方案的验算依据`、`解释方案的目标值`、`解释方案的容量使用`、`展示方案的选择情况`。这些完整的结果追问允许主控选择 `read_verified_result`，再用 `explain_result` 选择事实编号，最终 `finish`。

默认读取当前会话中与有效输入、模板和版本一致的最近已验算方案；最近 100 条运行中没有匹配记录时明确拒绝，不借用旧参数的解。输入 `解释方案 #编号` 可显式查看当前会话历史方案，与有效需求不同的历史结果会注明原版本。模型不能自行换成其他编号。

源记录必须同时满足成功求解状态、可进行且通过的独立数学验算、工作流审核通过，并匹配当前用户和会话。候选、未接受、失败、其他会话和其他用户的记录都不能成为解释依据。工具提供目标值、状态、验算依据、适用的容量/供需指标和决策，每次最多 24 条事实；可用 `query` 按决策实体筛选。生成解释和最终返回前都检查源记录指纹、接受状态和当前版本，失效记录不能继续使用；已生成但未接受的解释标记为 `UNACCEPTED_ANALYSIS`。

LLM 选择相关 `fact_ids`，程序生成数值文本与 `fact_citations`（源运行、源版本、事实编号、字段路径）；不存在、重复或未覆盖明确追问内容的引用被拒绝。当前解释没有自由文本推导，也不把验算通过换算成模型自报的“正确概率”。复杂“为什么”、敏感性、不可行诊断仍需增加专用证据工具。

解释另建 `ANALYSIS` 运行记录，`result_reference` 指向源方案，原求解记录和有效需求不被改写。解释的 `workflow_verification.scope=verified_result_reference`，不产生新的数学验算成功标记或求解目标值，也不开启本轮 Solver。含有额外修改的消息不能直接走结果解释捷径。

## 上下文管理

核心输入为本轮消息、有效需求摘要、数据版本、可用行动、当前结果和验证状态；可选输入为最近对话、相关显式记忆和工具观察。完整表格及历史需求版本保留在本地，主控通过工具使用数据引用。

预算包含消息封装和行动 Schema 的保守预留。UTF-8 字节数用于无需模型分词器的保守估计，并非供应商实测 token 用量。超限先移除较旧对话、可选记忆及旧观察；核心需求或最新观察仍超限则明确停止，禁止截断核心约束和数值。核心需求不由历史聊天摘要重建。

远程模式会发送本轮消息、有效需求摘要和保留下来的历史、记忆、工具反馈。按需读取的字段及结果事实也属于工具反馈，可能发送给已配置的模型服务。这版没有实现严格离线策略或全面敏感数据脱敏，禁止据此宣称数据完全不出本地。

## 任务和显式记忆接口

任务状态保存在 `agent_task_states`，包含需求版本、待回答问题、最近运行及已验证运行引用、最近观察和停止原因。追问后的下一轮可以读取此前状态；这是轮次级恢复，不是进程崩溃后精确恢复到某个工具指令。清理对话运行记录时同步清理任务状态。

| 接口 | 用途 |
| --- | --- |
| `GET /api/agent/task?conversation_id=…` | 查看当前会话任务快照 |
| `GET /api/agent/memories?conversation_id=…&query=…` | 查看或检索显式记忆 |
| `POST /api/agent/memories` | 用户明确录入 `content`、`kind`、可选 `conversation_id` |
| `DELETE /api/agent/memories/{id}?conversation_id=…` | 删除指定作用域记忆 |

`kind` 支持 `preference`、`business_rule`、`terminology`。每项记忆记录用户、会话、来源和时间，模型没有记忆写入工具。记忆是背景参考，不能静默替换已确认需求。

登录用户可保存个人级或会话级记忆，当前会话检索二者；匿名用户必须指定有效会话。检索先隔离作用域，再使用中文二字片段和英文关键词排序。删除会话同时删除该会话的记忆；仅清理运行记录会保留显式长期记忆。

现有登录机制仍是演示级，不构成生产认证承诺。项目级记忆、记忆修正/失效和语义向量检索尚未实现。

## 演示与验证

执行 `.venv/bin/python scripts/run_llm_agent_demo.py` 在临时数据库运行两轮真实求解，主控响应为脚本化模拟；这不是实际 LLM 成绩。

加 `--followup` 执行三轮：真实背包求解 → 带原文依据的容量修改并求解 → 读取新版本方案并生成事实引用解释。默认仍使用脚本化决策；可与 `--live` 组合进行模型验收，但需要已有配置认证正常。

加 `--live --user-id 用户ID` 会从现有数据库只读获取该用户的既有配置，再在临时数据库调用模型处理合成案例。不写入开发环境会话、配置或运行记录。未指定用户时只读取匿名作用域配置，不借用其他用户配置。

执行 `.venv/bin/python -m unittest discover -s tests -p 'test_llm_controller.py' -q` 验证动态顺序、验算门控、预算、错误、上下文和记忆隔离。

执行 `.venv/bin/python -m unittest discover -s tests -p 'test_agent_followup_tools.py' -q` 验证修改证据、原子批次、并发冲突、版本和作用域、来源失效及解释事实覆盖。

行动结构参考：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。兼容服务需要支持本版的严格 JSON Schema；不支持时明确报告失败，首版不自动降级结构化协议。
