# LLM 驱动 Agent、上下文与记忆实施计划

制定日期：2026-10-05。目标是由 LLM 根据任务状态和工具反馈逐步选择行动；求解、校验和有效需求版本由程序管理。

## 第一阶段：可运行主控与任务记忆（工程已完成）

1. 增加结构化行动合同和有预算的 LLM 决策循环，复用已有需求分析、数据检查、模型、Solver、Verifier 和方案比较能力。
2. 配置模型后自动进入主控循环；无配置使用既有规则工作流，可显式选择旧模式。模型失败明确记录，不能伪装成模型成功。
3. 保存会话任务快照：有效需求版本、待解决问题、最近运行引用、工具观察及结束原因。对话回复可恢复任务；隔离不同用户和会话。
4. 建立统一上下文组装：当前用户输入、有效需求摘要、工具能力、必要历史、相关记忆及执行反馈。按输入预算移除可选内容；核心需求超限时明确停止，禁止截断数值和约束。
5. 增加用户明确录入的长期记忆及读取、删除接口，记录类型、来源、作用域；模型不能自行把假设升级为已确认记忆。
6. 接入现有 HTTP、SSE、运行记录与审计轨迹，求解结论仅在验算通过后接受。所有新代码包含中文注释。

验收：脚本化模型响应配合真实求解验证动态行动顺序、验证门控、错误反馈、预算停止、跨轮版本继承、上下文裁剪及记忆隔离；运行既有回归。真实模型另做少量合成数据冒烟，分别报告接口可用性和任务效果，不将模拟响应计作真实模型成绩。

## 第二阶段：语义修改与结果分析（首批工具已实现）

- LLM 提交带原文依据的结构化需求变更，程序检查数值、单位、实体、条件覆盖和版本冲突后原子提交。
- 增加已验算结果按需读取、解释、不可行诊断与场景分析工具；解释中的关键事实绑定结果引用。
- 完善步骤级中断恢复、取消、幂等性、上下文外发记录和运行成本统计。

当前已完成的范围：背包容量/物品数值与运输供需/既有线路成本的原文修改；有效版本比较提交；已验算结果按作用域和版本读取；LLM 选择事实、程序生成引用解释；运输模型的供需/网络不可行诊断。任意新增约束、自由因果解释、场景证据、中断恢复、取消和供应商实测费用仍在第二阶段后续任务中。

## 第三阶段：长期记忆与真实评测

- 记忆修正、失效、项目作用域及相关性检索；按实际效果决定是否引入向量检索。
- 独立单轮与多轮评测，与相同模型、工具条件的基线比较。报告语义正确、遗漏、错误放行、记忆准确、调用成本和延迟。
- 加固身份认证、密钥保存与严格本地模式，再开展多人或真实敏感业务试用。
